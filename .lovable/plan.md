# שיתוף Flipbook שעובד גם למי שלא מחוברת

## הבעיה
מסך `/flipbook?token=...` שולף את הסיפור ואת העמודים ישירות מהטבלאות `stories` ו-`story_pages`. הטבלאות האלה מוגנות והן מחזירות אפס שורות לצופה שאינה מחוברת, ולכן המסך נכשל ומפנה למסך הרשמה. השליפה של פרטי הספרון עצמו כבר עוברת דרך פונקציה ציבורית (`get_public_book`) ועובדת — רק שני השלבים שאחריה נשברים.

## הפתרון המוצע
להעביר את הזרימה הציבורית לפונקציות ה-RPC הציבוריות הקיימות, בלי גישה ישירה לטבלאות:

```text
token ב-URL  ->  get_public_book(token)   -> מאמת שהספרון קיים ומסומן ציבורי
              ->  get_public_story(id)    -> מחזיר את הסיפור + כל העמודים במכה אחת
```

## האם צריך RPC נוסף ל-story_pages?
לא. `get_public_story` כבר מחזירה את העמודים בתוך התשובה שלה — מספר עמוד, טקסט וכתובת האיור — וזה בדיוק מה שהמסך צריך. אין צורך בפונקציה חדשה ואין צורך במיגרציה.

## מה בדיוק נחשף לצופה הציבורית
רק מה שנדרש להצגה:
- שם הילד/ה, נושא הסיפור, טווח גיל, שפה, מגדר, תמונת כריכה
- לכל עמוד: מספר עמוד, טקסט, כתובת איור

מה שלא נחשף: מזהה המשתמש הבעלים, ההקדשה האישית, תאריכי יצירה, נתוני חיוב/קרדיטים, נתיב תמונת הילד/ה. גם כיום ההקדשה מוסתרת בצפייה ציבורית וזה יישאר כך.
האיורים עצמם ממשיכים להישלף דרך הפונקציה שמנפיקה קישור חתום ומאמתת את הטוקן — ללא טוקן תקין אין תמונות.

## מה משתנה בקוד
- `src/pages/FlipbookViewer.tsx`: בזרימת הטוקן — לקרוא ל-`get_public_story` עם מזהה הסיפור שהתקבל מ-`get_public_book`, ולמפות ממנה את הסיפור והעמודים. להסיר את שתי השאילתות הישירות ל-`stories` ו-`story_pages` במסלול הזה.
- מסלול הבעלים (`/flipbook/:bookId`, משתמשת מחוברת) נשאר כפי שהוא, כולל ההקדשה.
- טיפול בשגיאות: טוקן לא תקין או ספרון שאינו ציבורי -> הודעה ידידותית "הספרון לא נמצא או שאינו משותף" במקום הפניה לדף הבית/הרשמה.
- כפתור השיתוף וכותרת המסך ימשיכו לעבוד על בסיס אותם שדות.

## בדיקה
פתיחת קישור השיתוף בדפדפן ללא התחברות ווידוא שהעמודים והאיורים נטענים ושאין הפניה למסך הרשמה.
