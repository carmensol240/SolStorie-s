- Subdirectories have their own AGENTS.md (supabase/functions/AGENTS.md); read it before changing files there.
- Passwordless email login uses our own send-login-code / verify-login-code functions (hashed codes in login_codes, sent via Resend), never supabase.auth.signInWithOtp. Why: the auth account must be created only after the code/link is verified, with our own rate limits.
- Story creation: the client sends a one-time client_request_id; generate-story first inserts the story row (unique per user+ID), charges only after that insert, returns the existing story on conflict, and deletes the row + refunds on any unfinished exit. The in-progress mark lives in src/lib/story-generation-session.ts; auto-reloads (deploy poll, service worker) wait while it is valid or on /create; never call supabase.auth.refreshSession() manually. Why: reloads, re-login and retries must never lose, duplicate or double-charge a story.
- Story access: an owned non-taste story created before LEGACY_UNLOCK_CUTOFF (supabase/functions/_shared/legacy-access.ts) counts as open even without a story_unlocks row; grantStoryAccess retries and alerts admin on failure. Why: old credit stories must never hit a paywall.
- Admin view mode: server table admin_view_mode + is_effective_admin(uuid) decide admin bypasses (paywall, coloring, PDF, edits, page-1 retry, and any future credit skip); admin pages use raw has_role. Why: an admin in demo mode must experience the site exactly as a parent, and non-admins can never set it.
- Story reader shows illustrations via getReadingIllustrationUrl (storage render/image, ~1000px WebP, object-contain); print/PDF and coloring always use getPublicIllustrationUrl originals. Why: fast reading without affecting print quality.
- Service worker (vite.config.ts): skipWaiting+clientsClaim+cleanupOutdatedCaches+navigationPreload, no precache navigateFallback; navigations are NetworkFirst with the precached index.html only as offline fallback, sign-in URLs NetworkOnly, images runtime-cached. public/sw-no-cookies.js (importScripts) sends same-origin static/precache fetches with credentials omit, and the deploy poll in main.tsx also omits cookies. src/lib/sw-recovery.ts unregisters the SW + app-shell caches (never story-illustrations/IndexedDB) and reloads once per 10 min on asset 404 / chunk / ReferenceError. main.tsx reloads once on controllerchange, but in /story/ shows a "new version" toast. Why: the host pins visitors to a deployment with a __dpl cookie that only real navigations refresh; SW-forwarded fetches are not navigations.
- The reader auto-saves an owned, ready, non-demo book to IndexedDB after first display (requestIdleCallback if present, else 2s timeout); every browser API is feature-checked. Why: "read without internet" must work on iPhone too.
- Storage writes happen only in server functions (service key); story-illustrations is public for direct/render URLs but has no anonymous SELECT policy (no listing). Why: security scan + unguessable story-ID folders.
- /create keeps steps 1-3 in the URL (?step=N, forward = push) and saves answers per tab in sessionStorage via src/lib/create-draft.ts (key includes user ID, never image data; cleared on story success, sign-out, "new profile"). Why: browser/phone Back must move between steps without losing input.
- Page text passed to an image model always goes through storyTextForPrompt (supabase/functions/_shared/style-config.ts): nikud stripped and marked "meaning only, never write it". Why: raw quoted Hebrew made the model paint it as a caption inside the saved picture.
- Print PDF (src/hooks/use-pdf-export.ts + src/lib/print-layout.ts): 216 mm square pages (21 cm + 3 mm bleed) rendered at 300 DPI, text/logo/page numbers ≥13 mm from the edge, pictures contain-fit over a blurred fill, page order from buildPageSequence (cover, inside cover, dedication, text even / picture odd, a picture-less story page joins the previous text page (max 2 per page, font auto-fit 54→40px then line-height 1.9→1.6, then reflow), decorative page only when no join is possible, then talk page + "next adventure" (QR to /create?from=book, no personal data), fillers draw-moment → our-hero → blank to a multiple of 4, back cover last). Print-only upscaled copies come from upscale-print-illustrations (owner + server PDF entitlement in _shared/pdf-entitlement.ts), stored once in story_pages.print_illustration_url; failure falls back to the original. Why: real print-shop output without touching reader pictures.
- Online coloring uses fixed CANVAS_LONG_SIDE resolution; resize changes CSS only. Save/print use coloring-a4.ts, A4 only. Empty pages go through normalizeColoringPixels in _shared/coloring-pixels.ts (threshold only after inspectColoringPixels passes, otherwise toLineArt); painted exports set preserveColors. Server generation goes through _shared/coloring-pipeline.ts (check → limited retries → extractOutlines from the original). Why: no lost drawings, colored sheets, solid black blobs or half-A4 PNGs.
