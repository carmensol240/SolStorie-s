- Parent-chosen appearance (hair/clothes) is turned into one English character description by supabase/functions/_shared/appearance.ts and added to every illustration, retry and coloring prompt; form values sent with the request win over the saved profile. Why: keeps the child identical on every page.
- Illustration pages: main image service retries only transient errors; safety blocks are never replayed or reworded (page is held for admin); the backup must receive the same style text, character lock and reference images, and a backup picture that fails the strict look check is not saved. Why: keeps every page consistent and respects the AI refusal rules.
- Grow webhook: the package in cField2 is granted only when the amount paid matches a price in supabase/functions/_shared/package-prices.ts (or that price minus an active discount coupon); otherwise the admin is alerted and only the package matching the amount is granted. Any price change must update package-prices.ts too. Why: cField2 is in the checkout URL and the buyer can edit it.
- Passwordless email login uses our own send-login-code / verify-login-code functions (hashed codes in login_codes, sent via Resend), never supabase.auth.signInWithOtp. Why: the auth account must be created only after the code/link is verified, with our own rate limits.
- Story creation: the client sends a one-time client_request_id; generate-story first inserts the story row (unique per user+ID), charges only after that insert, returns the existing story on conflict, and deletes the row + refunds on any unfinished exit. The in-progress mark lives in src/lib/story-generation-session.ts; auto-reloads (deploy poll, service worker) wait while it is valid or on /create; never call supabase.auth.refreshSession() manually. Why: reloads, re-login and retries must never lose, duplicate or double-charge a story.
- Story access: an owned non-taste story created before LEGACY_UNLOCK_CUTOFF (supabase/functions/_shared/legacy-access.ts) counts as open even without a story_unlocks row; grantStoryAccess retries and alerts admin on failure. Why: old credit stories must never hit a paywall.
- Admin view mode: server table admin_view_mode + is_effective_admin(uuid) decide admin bypasses (paywall, coloring, PDF, edits, page-1 retry, and any future credit skip); admin pages use raw has_role. Why: an admin in demo mode must experience the site exactly as a parent, and non-admins can never set it.
- NLP techniques, topic types and the post-generation check/fix live in supabase/functions/_shared/nlp-techniques.ts; the result is saved to stories.nlp_report and a failed check never blocks or charges differently. Why: one source for the instructions, the check and the admin review.

- The character core (face, skin, eyes, hair, glasses, body) and the outfit line are built separately in supabase/functions/_shared/appearance.ts; a kippah is allowed only for a boy when the form sends appearance.kippah (saved on stories.kippah/kippah_color; retries and coloring read only the story, never children.kippah), tzitzit/sidelocks never, and a story without parent clothes saves one fixed outfit in stories.story_outfit. Why: a future character card must never carry clothes, and every page/retry/coloring page must show the same clothes.
- Story reader shows illustrations via getReadingIllustrationUrl (storage render/image, ~1000px WebP, object-contain); print/PDF and coloring always use getPublicIllustrationUrl originals. Why: fast reading without affecting print quality.
- New-story page length: generate-story splits any page over MAX_PAGE_CHARS (supabase/functions/_shared/page-split.ts, counted without nikud) into an extra text-only page after the NLP check; picture assignment uses the original numbering. Why: every page must fit a phone without squeezing text.
