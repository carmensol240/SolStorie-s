- New-story page length: generate-story splits any page over MAX_PAGE_CHARS (supabase/functions/_shared/page-split.ts, counted without nikud) into an extra text-only page after the NLP check; picture assignment uses the original numbering. Why: every page must fit a phone without squeezing text.
- Any AI-written or AI-rewritten Hebrew page text (generate-story, swap-gender, enhance-text with storyId) passes through _shared/hebrew-editor.ts before saving: one call with all pages, safety checks per page (names kept — compared also without ו/י so vocalized spellings pass — and a length limit), one nikud retry for unvocalized 3+-letter words, and the original text on any failure. generate-story uses safetyNet: pages the editor failed/refused or that still have Latin letters or missing nikud go back up to 2 more times with the reason (runs that don't fit the time limit continue in the background), and pages still failing are saved in stories.text_issues, which keeps the story needs_attention (refreshStoryReadiness) and sends one admin alert + email per story (_shared/story-text-alert.ts). Why: a story must never be delivered silently with raw text, without risking the story or the charge.
- A family member in the reserves/army gets its uniform lock only from _shared/military-family.ts (role from topic id, Hebrew title or story text; scene decides uniform vs home clothes), used by generate-illustrations and retry-illustration. Why: one rule for first drawings and redraws.
- "Let's talk about the story" questions live in stories.talk_questions: written in the Hebrew editor's same call (_shared/talk-questions.ts), cleared on gender swap, and otherwise made once by story-talk-questions (owner/admin) when the reader end or print file needs them. Why: no extra AI call for new Hebrew stories and one fixed set per story.
- Talk questions speak to the child as the hero in second person and never name the hero; sanitizeTalkQuestions drops any question containing the hero's name. Why: the reading child is the hero.
- The story's gender (stories.child_gender, else the form) wins over a saved children.avatar_description: _shared/profile-gender.ts aligns the profile (and rewrites the saved one), and illustration prompts use genderSymbolRestriction/negativePromptFor from style-config.ts so one request names only one gender. Why: an old saved profile put "girl" and "BOY" into the same request.
- New-story pictures and cast: _shared/story-cast-pages.ts plans the illustrated pages given to the writer (usual pattern + a taste's last page) and, after page split, forces a picture on the taste's last page and on each SolStories cast member's first page (adding the cast description to that prompt). Why: a taste must end on a picture, new characters must be seen when introduced, and existing stories must not be rewritten.

Why: every picture is 3D, hair comes only from the avatar, and no child appears who is not on the page.
