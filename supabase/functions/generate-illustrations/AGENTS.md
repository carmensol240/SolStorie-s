- Illustration pages: every redraw after a failed look check (child, 3D style, not photo-realistic, hero face visible incl. profile, text, outfit) is checked again, max 2 redraws; then only a "hero not visible" picture may be kept, anything else is held, and both cases send an admin alert + email. When the page already had a picture, redraws are saved under candidates/ and replace page-N.png only after passing; otherwise the old picture stays (alert + email). Main image service retries only transient errors; safety blocks are never replayed or reworded (page is held for admin); the backup must receive the same style text, character lock and reference images, and a backup picture that fails the strict look check is not saved. Why: keeps every page consistent and respects the AI refusal rules.
- generate-illustrations accepts a single-page redraw from a server-checked admin (is_effective_admin) on any story; owners are unchanged, and the function never charges or touches page1_regen_used. Why: admins fix customer pictures without signing in as them.
- generate-story sends firstDrawing:true with each per-page dispatch; generate-illustrations treats a single page as a redraw only without it, so first drawings save stories.story_outfit. Why: every first drawing is single-page, so outfit was never saved.
- generate-illustrations finds the face and child from the story itself (owner, child_id, then stories.child_photo_path), never from the caller; a redraw (single page without firstDrawing) without any face is refused (422); generate-story refuses a story with no face source (_shared/face-required.ts) before any row, charge or AI call. Why for both: first drawings are single-page too, so the old guard stuck faceless stories. Every first drawing saves the final outfit in stories.story_outfit and redraws (generate/retry) use it first; verify-purchase testMode is admin-only (has_role). Why: admin redraws ran under the admin account and drew a faceless child in different clothes.
- Picture shape: stories.illustration_format is decided once in generate-story from the SQUARE_ILLUSTRATIONS secret (_shared/illustration-format.ts: off/test=admin owners only/on; admin IDs in SQUARE_TEST_USER_IDS get squares even when off, and narrow "test" to them); generate-illustrations and retry-illustration append formatRule (explicit landscape 3:2 / square / portrait text) to every drawing, and the measured picture size is a check problem ("wrong shape", shapeProblems) that gets corrected redraws. Why: square can be switched off instantly, and the tall avatar sent first made landscape pages come out tall.
- Story-page pictures take the SolStories cast only from the page's own text (castInText / castReferenceBlock / pageCastRule in _shared/story-cast-pages.ts, used by generate-illustrations and retry-illustration): official look, each character once, absent cast members excluded; the writer prompt introduces cast members only with CAST_INTRO_HE and never describes their looks. Every page prompt carries NO_FOREIGN_FLAGS_RULE through CHARACTER_CONSISTENCY_PROMPT plus NO_FLAGS_NEGATIVE. Why: duplicated or unmentioned friends, wrong outfits and US flags appeared in pictures.
- Leo has one description (LEO_DESCRIPTION in _shared/style-config.ts, used by CAST_DESCRIPTIONS and CHARACTER_CARDS) and one identity reference picture (LEO_REF_URL in our own topic-images storage). generate-illustrations and retry-illustration add that picture after the hero's own pictures only when Leo is named on the page and the hero is not called Leo. Why: Leo must look the same everywhere without touching the hero's face pipeline.
- Look check vs page 1 (_shared/look-check.ts, used by generate-illustrations checkIdentityMatch on gemini-3.8-flash, the model the old 2.5-flash id is served by): eyes, hair tone, render style, outfit and chest emblem are separate answers; a page failing only these gets one redraw with the differences named, and if any try failed only on look the closest is kept with identity_check prefixed LOOK_KEPT_PREFIX, which keeps the story needs_attention (refreshStoryReadiness) + admin alert. public.mark_stuck_stories (pg_cron every 10 min) moves stories from the last 2 days stuck in generating/generating_illustrations with no illustration log for 15 min to needs_attention + admin_alerts. Why: the vague check passed blue eyes/flat style, and cut-off redraws left stories "in preparation" forever.
- First drawing of page 1 (the cover) is checked only against the child's avatar (same child, hair, eyes, Pixar-like 3D, plus the general picture checks) via checkCoverAgainstAvatar + _shared/cover-check.ts — never for clothes, emblem or a missing page-1 reference — and after the redraws it always keeps the closest try (cover_url updated, identity_check COVER_KEPT_PREFIX → needs_attention + admin alert). Pages 2+ and redraws of an existing page keep their own rules. Why: page 1 is everyone else's reference, so an empty cover broke the share page and the whole book.
- Stories created from AVATAR_TRAITS_CUTOFF (_shared/avatar-traits.ts): the age in every drawing instruction is children.age (age range only without it); hair shade/eyes/skin are read once from the avatar in generate-illustrations, saved on stories.hero_* (first save wins) and written the same on every page/redraw with avatarWinsRule; an empty children.hair_color gets the matching form value. Every page is also checked against the avatar (face/age/hair) as look problems, so a failure gets one redraw and then keeps the closest picture (never empty). Why: the text range drew a younger child and lighter hair than the avatar.
- Every story-picture instruction comes from buildIllustrationPrompt (_shared/illustration-prompt.ts) in generate-illustrations (main, backup, Flux, toddler second picture) and retry-illustration: face paragraph first with the child's avatar as the ONLY face reference (photo_url only when there is no avatar), the page reference only for clothes + 3D style ("do not copy the face"), one RULES block; pictures attached face → page reference → Leo. Every picture passes the mandatory 3D Pixar check (_shared/style-check.ts pixar_3d) and redraws also face/age/hair vs the face reference; failures get up to MAX_STYLE_REDRAWS corrected redraws, then the previous picture stays (a page 1 with no picture keeps the closest, preferring a 3D try) + admin alert (_shared/illustration-alert.ts); a check that cannot run is asked twice and never passes silently. Why: long rules and page 1's face drowned the avatar, and flat 2D redraws were saved unchecked.
- Stories from LIKENESS_CUTOFF (_shared/avatar-traits.ts), or any story with saved stories.hero_traits (likenessFlags, used by generate-illustrations and retry-illustration; also turns on the avatar hair/eye/skin tones): the avatar analysis also saves 3–8 distinguishing features in stories.hero_traits (first save wins), written in the face paragraph and checked as "avatar features" (a look problem); camera-framing uses CLOSE_CAMERA_ANGLES (waist-up on 2 of 3 pages, hero about half to 60% of the height). Why: children without standout traits were drawn as a generic Pixar child; an admin can opt one older story in by saving its features.
