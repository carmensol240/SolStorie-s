- Parent-chosen appearance (hair/clothes) is turned into one English character description by supabase/functions/_shared/appearance.ts and added to every illustration, retry and coloring prompt. With a face picture (avatar/photo) face and hair come only from the picture (heroHair); form hair is used only without one; form clothes always apply. A child with a saved avatar is never drawn without it: generate-story/generate-illustrations fall back to children.avatar_url and refuse (before charge / per page) when no face reference can be prepared. Why: keeps the child identical to the avatar on every page.
- Illustration pages: every redraw after a failed look check (child, 3D style, not photo-realistic, hero face visible incl. profile, text, outfit) is checked again, max 2 redraws; then only a "hero not visible" picture may be kept, anything else is held, and both cases send an admin alert + email. When the page already had a picture, redraws are saved under candidates/ and replace page-N.png only after passing; otherwise the old picture stays (alert + email). Main image service retries only transient errors; safety blocks are never replayed or reworded (page is held for admin); the backup must receive the same style text, character lock and reference images, and a backup picture that fails the strict look check is not saved. Why: keeps every page consistent and respects the AI refusal rules.
- Grow webhook: the package in cField2 is granted only when the amount paid matches a price in supabase/functions/_shared/package-prices.ts (or that price minus an active discount coupon); otherwise the admin is alerted and only the package matching the amount is granted. Any price change must update package-prices.ts too. Why: cField2 is in the checkout URL and the buyer can edit it.
- NLP techniques, topic types and the post-generation check/fix live in supabase/functions/_shared/nlp-techniques.ts; the result is saved to stories.nlp_report and a failed check never blocks or charges differently. Why: one source for the instructions, the check and the admin review.
- The character core (face, skin, eyes, hair, glasses, body) and the outfit line are built separately in supabase/functions/_shared/appearance.ts; a kippah is allowed only for a boy when the form sends appearance.kippah (saved on stories.kippah/kippah_color; retries and coloring read only the story, never children.kippah), tzitzit/sidelocks never, and a story without parent clothes saves one fixed outfit in stories.story_outfit. Why: a future character card must never carry clothes, and every page/retry/coloring page must show the same clothes.
- New-story page length: generate-story splits any page over MAX_PAGE_CHARS (supabase/functions/_shared/page-split.ts, counted without nikud) into an extra text-only page after the NLP check; picture assignment uses the original numbering. Why: every page must fit a phone without squeezing text.
- Any AI-written or AI-rewritten Hebrew page text (generate-story, swap-gender, enhance-text with storyId) passes through _shared/hebrew-editor.ts before saving: one call with all pages, safety checks per page (names kept, length limit), one nikud retry for unvocalized 3+-letter words, and the original text on any failure. Why: gender agreement, whole sentences and full nikud without risking the story or the charge.
- A family member in the reserves/army gets its uniform lock only from _shared/military-family.ts (role from topic id, Hebrew title or story text; scene decides uniform vs home clothes), used by generate-illustrations and retry-illustration. Why: one rule for first drawings and redraws.
- "Let's talk about the story" questions live in stories.talk_questions: written in the Hebrew editor's same call (_shared/talk-questions.ts), cleared on gender swap, and otherwise made once by story-talk-questions (owner/admin) when the reader end or print file needs them. Why: no extra AI call for new Hebrew stories and one fixed set per story.
- generate-story must answer the browser within ~150s (platform cut-off): the story-writing call runs with low reasoning (its hidden thinking otherwise cuts the JSON off), the Hebrew editor's timer ends by ~125s after the request began, and each illustration dispatch is re-sent up to 2 times only on a 503 (function never started). Why: a cut-off request leaves an empty story with a charged credit and no refund.

- generate-illustrations accepts a single-page redraw from a server-checked admin (is_effective_admin) on any story; owners are unchanged, and the function never charges or touches page1_regen_used. Why: admins fix customer pictures without signing in as them.
- generate-illustrations finds the face and child from the story itself (owner, child_id, then stories.child_photo_path), never from the caller; a single-page redraw without any face is refused (422). Every first drawing saves the final outfit in stories.story_outfit and redraws (generate/retry) use it first; verify-purchase testMode is admin-only (has_role). Why: admin redraws ran under the admin account and drew a faceless child in different clothes.
- The story's gender (stories.child_gender, else the form) wins over a saved children.avatar_description: _shared/profile-gender.ts aligns the profile (and rewrites the saved one), and illustration prompts use genderSymbolRestriction/negativePromptFor from style-config.ts so one request names only one gender. Why: an old saved profile put "girl" and "BOY" into the same request.
- Talk questions speak to the child as the hero in second person and never name the hero; sanitizeTalkQuestions drops any question containing the hero's name. Why: the reading child is the hero.
